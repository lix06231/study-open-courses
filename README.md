# study-open-courses

`study-open-courses` 是一套面向**人类学习**的 Codex Skill：先找到经过真实学习者验证、又适合当前用户的学习资源，再获取完整可信的内容，最终重构成真正能学的课程或学习指南。

它的核心原则是：

> **大众验证负责入围，学习适配负责排名。**

名气、播放量和学校招牌都不能单独决定推荐结果。候选资源先通过 Community Validation，再按用户水平、目标、时间、完整性、时效性和可访问性排序。

## 它解决什么问题

用户可能从两种入口开始：

- 已经指定课程、书籍、PDF、视频系列、播客、访谈、教程或官方文档；
- 只有一个学习目标，还不知道应该学哪份资源。

第二种情况下，Skill 只补问真正影响选择的信息，通常是学习主题、当前水平、目标和时间，不做冗长测评。它通常推荐 1–3 个候选，并给出一个明确首选。

## v3 流程

```text
Learning Goal / 已指定资源
        ↓
Learning Resource Discovery
        ↓
Community Validation（准入）
        ↓
Learner Fit Ranking（排序）
        ↓
Learning Suitability
        ↓
Source Resolver
        ↓
Content Ingestion
        ↓
Integrity Check + Evidence & Provenance
        ↓
Learning Reconstruction
        ↓
Learning Compression（可选）
        ↓
Publishing（正式课程默认 MD + HTML + PDF）
```

课程页面、syllabus 和目录只能证明“这门课可能讲什么”，不能冒充课程正文。进入重构前，Skill 会检查缺课、重复、截断、版本冲突、字幕或 OCR 质量，并保留课节到来源的映射。

## 与仓颉类 Skill / 知识蒸馏的区别

本项目借鉴了三类有价值的思想：

- 支持课程之外的多种内容类型；
- 把内容获取与内容处理解耦；
- 让最终产物能够追溯到原始来源。

但 `study-open-courses` 不会因此变成“万能内容蒸馏器”。

| 维度 | study-open-courses | 仓颉类 / 通用知识蒸馏思路 |
|---|---|---|
| 主要对象 | 想学会某件事的人 | 任意内容的提取、压缩或知识化 |
| 首要问题 | 什么资源可信且适合这个学习者 | 如何把输入转成更紧凑的知识表示 |
| 输入范围 | 多类型，但必须服务明确学习目标 | 往往强调尽可能广的内容兼容性 |
| 推荐机制 | 大众验证准入，学习适配排序 | 通常不以学习者选课为核心 |
| 获取与处理 | 明确分开 | 借鉴并保留这一思想 |
| 完整性 | 重构前必须检查缺失、重复和版本 | 视具体系统而定 |
| 压缩顺序 | 先建立可学习结构，再决定是否压缩 | 压缩常常是主要目标 |
| 不可替代内容 | 转为导读、伴读或观看辅助 | 可能仍被当作可蒸馏输入 |
| 最终产物 | 课程、学习指南、练习与理解检查 | 摘要、知识库、结构化知识或模型上下文 |
| 服务对象 | 人类学习者 | 可能包括模型、知识库或自动化系统 |

一句话概括：

> 仓颉类方法帮助我们更可靠地“拿到并追踪内容”；`study-open-courses` 负责判断“人该学什么、怎样才真正学得会”。

## Learning Suitability

不是所有好内容都应该被压缩成课程：

- **适合课程重构：** 知识、技能、技术和方法论内容；
- **适合辅助学习：** 原始体验很重要，但导读和问题能够帮助理解；
- **不应替代原作：** 文学、艺术或强体验型作品。

例如《活着》更适合做时代背景、人物关系、主题问题和阅读路径，而不是承诺一门“两小时替代原作”的蒸馏课。

## 支持的输入

- 公开课和系列课程；
- 书籍、PDF、EPUB 和网页正文；
- 系列视频、播客、长访谈；
- 教程、讲义、Slides、练习；
- 官方文档；
- 为一个学习目标设计的少量多源组合。

支持某种输入，不等于保证能够合法、完整地取得内容。登录、付费、地区限制、版权和缺失材料都会在交付物中如实说明。

## 最终交付物必须说明

- 学习者、目标、先修要求和时间；
- 学习路径、解释、例子、练习和理解检查；
- 每一部分依据哪些来源；
- 缺失内容、冲突、不确定性和访问限制；
- 压缩时删掉、合并或延后的内容；
- 下一步，以及什么时候应该回到原课程或原作。

## 默认交付格式

当用户要求“完成课程”“正式课程”“做完后给我下载”或其他完整交付时，默认生成三份内容一致的文件：

- **Markdown（`.md`）：** 内容母版，便于继续编辑和版本管理；
- **HTML（`.html`）：** 适合电脑和手机阅读，包含目录导航、响应式排版和打印样式；
- **PDF（`.pdf`）：** 适合下载、打印和离线学习。

HTML 和 PDF 从同一份 Markdown 内容派生，不能各写一套导致课程结构、练习或来源说明不一致。发布前必须检查三种格式的标题、章节顺序、练习、出处、完整性缺口和压缩说明。

PDF 还要检查中文字体、分页、表格、空白页和文字裁切；HTML 要检查目录跳转、链接和本地资源。最终回复必须提供三个文件的可点击下载链接。

以下情况不强制三件套：

- 只是在推荐课程、确认范围或查看中间预览；
- 用户明确只要 Markdown、HTML 或 PDF 中的某一种/几种格式。

如果环境暂时无法生成其中一种正式格式，Skill 必须明确说明缺少什么和剩余工作，不能只给 Markdown 却声称完整交付已经完成。

## 仓库结构

```text
study-open-courses/
├─ SKILL.md
├─ README.md
├─ .gitignore
└─ docs/
   ├─ superpowers/
   │  ├─ specs/
   │  └─ plans/
   └─ validation/
```

`SKILL.md` 是可执行的 Skill 说明；README 面向使用者解释定位和边界；`docs/validation` 保存行为测试证据。

## 本地使用

可以把整个目录安装到 Codex 的 skills 目录，也可以从公开的 GitHub 仓库获取并安装。

示例请求：

```text
我是非技术背景，每周能学 3 小时，想系统理解 AI Agent。
请先推荐经过大量学习者验证、适合我的主课程，确认后再把它重构成学习计划。
```

也可以直接指定资源：

```text
请评估并学习这套课程。它刚发布不久，如果大众验证不足请明确告诉我，
但不要因此拒绝处理；先检查内容是否完整，再决定适合做课程还是辅助学习材料。
```
