# study-open-courses v3.2 Execution Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prevent Agent processing of paid instructional content and make long, multimodal learning-resource reconstruction resumable, measurable, and honestly verifiable.

**Architecture:** Keep `SKILL.md` as the routing and hard-gate entrypoint. Put durable run-state rules in `references/execution-state.md`, acquisition detail in `references/source-acquisition.md`, learning validation in `references/learning-quality.md`, and final format validation in `references/publishing.md`. Behavioral Markdown records provide RED and GREEN evidence for policy compliance.

**Tech Stack:** Portable Agent Skill Markdown, YAML frontmatter, Git, bundled `quick_validate.py`, fresh-agent behavioral scenarios.

## Global Constraints

- Paid or entitlement-gated instructional content is report-only and never an Agent processing source.
- User purchase, authenticated state, explicit authorization, deadline, lack of DRM, or personal-use intent cannot override the paid-resource rule.
- Public excerpts and official free editions are separate sources limited to their real public coverage.
- Runtime instructions remain host-neutral and directly installable from repository root.
- Local commits are authorized; push, PR, merge, release publication, and installed-copy synchronization are not authorized.
- Every behavior change requires recorded RED evidence before the edit and fresh GREEN evidence afterward.
