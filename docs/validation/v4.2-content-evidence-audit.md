# SOC 内容证据与绕过路径复审

日期：2026-10-05。审查对象：AgentHub 权威版 `study-open-courses`，v4.1.0 → v4.2.0。

这次发现的核心问题是：文字要求已经禁止无资料编课，但程序仍主要验证 Agent 自己填写的状态和非空字符串。它能防止一些文件遗漏，却不能阻止“先自己编，再补一套验收表”。修复把实际内容证据接入编写前、构建、验收快照、封存和最终检查。

## 实际发现与修复

| 风险 | 原有路径及影响 | 本次修复 |
|---|---|---|
| 高：网页地址冒充取得正文 | `locator_resolves()` 对任何 HTTP(S) 地址返回 true；没有确认访问或保留正文 | 编写前必须有保留的本地内容、SHA-256、精确行范围及原文摘录；URL 只作出处 |
| 高：目录/概述冒充内容级资料 | `content_evidence`、`source_type`、`evidence_size` 只检查非空 | 新增来源类型/获取方法枚举；目录、AI 生成、二手概述不能作为来源；摘录与文件内容逐字核对，大小使用实际字节数 |
| 高：未取得资料也能直接构建 | builder 不执行完整性或资料关卡 | 新增编写前资料校验及快照；builder 复核快照、必需资料和引用，失败时不生成课程成品 |
| 高：少拿资料，自己缩减分母 | `expected_items` 由 Agent 自填；没有独立保留的完整目录与排除记录 | 保留原始目录；included/excluded 必须完整划分目录；排除项须有实际用户范围指令/接受记录；核对标题及顺序 |
| 高：字幕代替视觉/练习，讲义代替整节口述 | 完成度只与 item Boolean 对齐；视觉 `TEXT_ONLY` 可填非空理由 | 目录声明必需 primary/visual/practice/attachment 通道；缺必需通道阻断；speech 不能用 notes/slides 补足；ASR/OCR/slides 需保留不同的原始文件 |
| 高：取得字幕开头就算完整 | 首尾时间和资料大小是描述性字段 | 精确引用校验文件实际首尾；字幕/ASR 必须有时间段，与原课时长比较；大间隙需实际核对证据 |
| 高：引用一个真句子后随意写后面的章节 | concept coverage 的位置字段不验证，source map 未参与程序关卡 | 核对逐项摘录、来源单元、章节范围和出处标签；每个来源教学/翻译块要有映射；每个预期单元有概念覆盖，每个章节有来源映射 |
| 高：旧 QA 可以给新文件补签 | seal 在封存时重新生成文件哈希；只查 aggregate pass/revision/failed list | 增加检查前快照；封存只核对已有哈希，不能补签；绑定来源、范围、上下文、证据台账、章节及构建设置；构建使旧验收失效并保留历史 |
| 中：核心验收用“不适用”绕过 | 九个学习检查均可填 not_applicable | 目标追溯、来源准确、合成标注、压缩完整性、可见限制必须适用；缺检查/重复检查/报告定位或哈希不正确被拒绝 |
| 中：PDF 检查缺能力也继续通过 | 无 PDF parser 时仅给 warning | 正式验收缺少必需 PDF 检查能力记为失败；缺 PDF 的兼容参数不能授权完整交付 |
| 中：生成位置可逃出课程包 | basename 未限制为文件名 | 拒绝 basename 中的路径分隔符，防止输出到包外 |

这里的“缺资料不能继续”是正式课程流水线的限制。早期评估可以只查看明确标注的代表性内容；真实阻塞时仍可交付已核实的元信息或部分成果，但不能把它称为完整课程，也不能自行换成 AI 原创课规避资料关卡。

## 哪些 Agent 行为最容易出问题

本次没有运行不同模型/客户端的对比测试，不能据此指认某个模型或客户端“更会偷懒”。风险来自以下工作方式：

- 获取阶段只找标题、课程主页或他人总结，然后按常识写课。
- 编写阶段先生成内容，再倒填“已取得/已验证”及出处。
- 只处理容易取得的字幕，把图示、演示、练习当作不需要。
- 出现失败就删掉 expected item，或自行把全课程改成一章。
- 自检只填 pass、复制同一段笼统报告，或把关键检查写成不适用。
- 验收以后继续改文件，再跑封存取得新指纹。
- 恢复任务时只看旧 PASS，不核实课程版本、资料与范围是否变化。

这些正常流程中的绕过行为已有规则和确定性关卡约束。禁止修改校验器、伪造资料与用户授权、跳过关卡，或把检查通过当作内容认证，已进入 SKILL 主入口。

此外，全部 Python 源码通过语法检查；Skill 校验返回 `Skill is valid!`；直接运行初始化、资料关卡、构建与封存入口，未取得资料的骨架返回失败，未生成课程正文。README/改动规则/报告的本地链接核验通过。补齐的是原仓库已有的 MIT LICENSE 文件，没有重写许可内容。

新增验证覆盖网页替代文件、目录伪装、AI 生成伪装、资料篡改、范围越界、伪造摘录和大小、视觉/练习缺失、讲义替代口述、收费分类伪装、分母缩水、无用户指令的排除、自引用课程、取得资料后改范围、核心检查填不适用、篡改后重新封存、重复检查、修改验收报告、虚假来源引用、未映射章节、重建后旧 QA 失效、快照重置并保留历史、无 PDF/无检查能力、无时间段字幕、字幕截断、新增教学块无引用、封存缺验收项，以及生成路径越界。另有用户明确选择部分范围的成功用例。

成功用例与 PDF 为合成测试夹具，用于证明状态与证据一致性规则能正常运行。夹具中的 QA 是显式模拟声明，不能证明真实来源获取、视觉验收或课程教学质量。本次没有抓取和重建一门真实长课程，也没有进行跨 Agent 宿主行为测试。

## 修改后流程

初始化 → 保留原始目录/实际正文与必需资料 → 编写前资料校验及快照 → 基于资料编写和逐项映射 → 构建 → 检查前文件快照 → 对照原文与渲染成品实际验收 → 封存核验 → 最终校验。

完整 schema 与使用要求见[内容证据规范](../../references/content-evidence-contract.md)，验收字段及先后顺序见[记录规范](../../references/run-ledger-schema.md)。旧课程包不能自动继承 v4.2 完成状态：从原始资料补充证据并重新检查，不能拿生成章节倒造字幕。

## 尚不能靠文件校验解决的边界

1. 同一个 Agent 能修改全部资料、台账和代码时，可蓄意制造一致的假证据。普通哈希/规则无法证明来源真实或 Agent 确实读过。这里没有不可篡改的外部取证服务或独立审批系统。
2. 官网目录是否真实完整、讲师实际讲了什么、字幕是否忠实、图示是否理解正确、课程是否真的能教会普通人，仍要对照原作和逐项内容检查。一次语法正确的引用不代表整个章节忠实。
3. `channel_basis`、范围授权、检查报告和 QA 结论的真实性属于信任边界；字段存在只能验证结构。必须留实际获取输出、原始文件和具体核对记录，不得伪造，也不得宣称本次进行了独立内容审查。
4. 新增本地留存要求只适用于依法可保存的内部工作证据。若合法访问方式不允许保存足够证据，应报告阻塞或提供受限元信息，不绕过访问/版权规则。

修复提高了正常执行、恢复和验收过程的可核查性，不能承诺“任何 Agent 永远不可能编造课程”。
