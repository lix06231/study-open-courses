# v4.1 deterministic pipeline validation

Date: 2026-09-11 (Asia/Hong_Kong)

## Scope

This record covers the v4.1.0 repository synchronization from the validated AgentHub source. It does not replace the earlier v3.2 simulated policy evaluators and does not claim cross-model behavior validation.

## RED baseline

Before the repository synchronization, branch `codex/v3.2-execution-hardening` at `5cc76ca` contained runtime v3.2.2. The repository had no `scripts/` or `tests/` pipeline, no initialized run-ledger/QA templates, no canonical Markdown builder, no artifact sealing, and no mechanical check that the standalone HTML contained all local image types. The written rules therefore could not mechanically reject stale QA, post-QA artifact changes, fake local locators, or course-pack path escapes.

This RED state was inspected and recorded before applying the v4.1 files to the repository. The implementation had already been developed and tested in the AgentHub authority, so this is prospective evidence for the repository synchronization rather than the original development chronology.

3. a stale artifact revision is rejected;
4. a remote runtime image is rejected;
5. an artifact changed after QA is rejected by its sealed hash;

8. a manifest path escaping the course pack is rejected.

## Evidence boundary

The scripts reconcile deterministic facts and recorded review evidence. They do not prove that an explanation is pedagogically excellent or that an Agent reviewed content honestly. The full Learning QA remains a model or human judgment, while sealing prevents that judgment from being silently reused after the reviewed files change.
